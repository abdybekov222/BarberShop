Версия 1.1 (локализация для Кыргызстана, бюджет ИИ $10) · Документ для дизайнеров, фронтенд- и бэкенд-разработчиков

## 0. Цели проекта и ключевые метрики

**Цель:** цифровая витрина премиум-класса + онлайн-запись + «Виртуальное зеркало» как главный дифференциатор и драйвер записей.

| Метрика | Целевое значение |
|---|---|

| Конверсия начатая → завершённая запись | ≥ 60% |

## 1. Рекомендуемый стек и архитектура

### 1.1. Архитектурный подход

Монорепозиторий, модульный монолит (API + веб-клиент) на старте, без микросервисов. Тяжёлые задачи (ИИ-генерация) выносятся в асинхронную очередь. Принцип: **клиент — тонкий, бизнес-логика и лимиты — только на сервере**.

`Клиент (Next.js, PWA-ready) → API (NestJS) → PostgreSQL / Redis / S3 → очередь задач (BullMQ) → воркер ИИ → AI-провайдер (fal.ai / Hairstyle API)`

| Слой | Технология и требования |

| Автоудаление фото | S3 Lifecycle (исходники — 7 дней, результаты — 14 дней) + ночной cron-job как вторая линия защиты; в БД — `expires_at`. Подробнее в 1.5 |
| Уведомления | Бесплатные каналы в приоритете: Telegram-бот, email. SMS — только OTP (напоминания по SMS — опционально, если позволяет бюджет) |

### 1.4. Данные и инфраструктура

- **PostgreSQL 15** — основная БД (транзакции, ограничения целостности для слотов).
- **Redis** — кэш, сессии OTP, лимиты, очереди.
- **S3-совместимое хранилище** (AWS S3 / Cloudflare R2 / Yandex Object Storage) — фото клиентов и результаты ИИ, доступ только по подписанным URL со сроком жизни.
- **CDN** (Cloudflare) — статика, медиа галереи, WAF, защита от ботов (Turnstile/reCAPTCHA на OTP).
- **Деплой:** Vercel (web) + Docker на VPS/Railway/Fly.io (API, воркеры), управляемые PostgreSQL и Redis. CI/CD — GitHub Actions (lint → test → build → deploy), окружения: dev / staging / prod.
- **Мониторинг:** Sentry (фронт и бэк), Grafana/Prometheus или Better Stack, аналитика — GA4 + Яндекс.Метрика, события воронки.
- **Админ-панель:** отдельный защищённый раздел `/admin` (роли: owner, admin, master) для управления услугами, мастерами, расписанием, галереей, записями и лимитами ИИ.

### 1.5. ИИ-модуль «Виртуальное зеркало» (экономичная архитектура, бюджет $10)

**Задача:** по фронтальному фото клиента показать вариант с выбранной стрижкой или бородой, сохранив лицо, цвет кожи и освещение.

**Бюджетные рамки:** $10 должны покрыть **200–500 генераций** (целевая цена не выше $0.02–0.05 за результат). При лимите 3 попытки на аккаунт это около 65–165 клиентов, использовавших весь лимит. Архитектура строится на трёх принципах: дешёвая модель; ничего платного до прохождения бесплатных фильтров; жёсткий потолок расходов с аварийным выключателем. Дорогие кастомные пайплайны (отдельные GPU-инстансы, длинные цепочки моделей) в MVP не используются.

**Два варианта реализации** (провайдер подключается через интерфейс `AiProvider`, замена — настройкой, без релиза):

| | Вариант А: API с оплатой за использование | Вариант Б: готовый Hairstyle / Face-Swap API |
|---|---|---|
| Что это | **fal.ai** (serverless GPU, оплата за генерацию) с лёгкими моделями класса **SDXL Lightning / Turbo**: inpainting по маске волос и бороды + сохранение лица. **Hugging Face** (бесплатные лимиты Inference API / Spaces) — только для разработки, тестов и аварийного резерва | Сторонние API «смена причёски / hair try-on» и face-swap с готовым результатом (например, YouCam API от Perfect Corp и аналоги на маркетплейсах API; список уточняется на R&D). Оплата за результат |
| Ориентир по цене (оценочно, проверить по актуальным тарифам) | Доли цента – несколько центов за изображение при 4–8 шагах генерации | Цель — не выше $0.05 за результат, чтобы $10 давали 200+ генераций |
| Плюсы | Полный контроль над промптами и каталогом стилей, нет привязки к одному вендору, самая низкая цена за кадр | Минимум разработки, не нужны GPU и подбор моделей, предсказуемая цена, быстрее MVP |
| Риски | Нужна настройка масок и промптов; качество «lightning»-моделей ниже, возможны артефакты; бесплатные лимиты Hugging Face нестабильны (очереди, холодный старт) | Каталог причёсок ограничен вендором; нужно проверить условия коммерческого использования, хранение фото у вендора, доступность из КР и способ оплаты (международная карта) |

**Выбор варианта — по итогам R&D (3–4 дня):** оба варианта прогоняются на 30 фото (разные лица, волосы, освещение). Критерии: доля приемлемых результатов не ниже 70% по оценке мастера, цена за результат, задержка не более 40 с, условия использования и приватность. Побеждает самый дешёвый вариант, прошедший порог качества. Рекомендуемый старт MVP — вариант Б (быстрее), вариант А — резерв и следующая итерация.

**Архитектурные требования:**

1. Интерфейс `AiProvider.generate(imageUrl, styleId, options) → jobId` и реализации `FalProvider`, `HairApiProvider`, `HfProvider` (dev/резерв). Активный провайдер задаётся в `salon_settings.ai_provider`.
2. **Платный вызов — всегда последний шаг.** Всё, что можно проверить бесплатно, проверяется до него: клиентская предпроверка в браузере (MediaPipe Face Detection: одно лицо, ракурс до ±20°, яркость, разрешение от 512×512) и серверная проверка на CPU (OpenCV/MediaPipe, open-source NSFW-классификатор) без платных API.
3. Оптимизация входа: сжатие до 768–1024 px по длинной стороне, JPEG q85, удаление EXIF (включая геолокацию) на сервере — дешевле и быстрее.
4. **Кэш результатов:** ключ = sha256 фото + `style_id` + версия модели. Повторный запрос возвращает готовый результат без вызова провайдера и без списания попытки.
5. Каталог стилей — 12–20 заранее протестированных образов с фиксированным `seed`, чтобы бюджет не тратился на неудачные промпты. Новый стиль добавляется из админки.
6. Асинхронность: BullMQ, concurrency 2, таймаут 60–90 с, один повтор только при сетевой ошибке; статус клиенту — polling каждые 2 с.
7. Результаты хранятся в приватном S3 и отдаются по подписанному URL (TTL 10 мин); на изображении подпись «ИИ-визуализация, результат может отличаться».
8. Бюджетный контроль: перед каждым платным вызовом резервируется его максимальная стоимость, после — фиксируется фактическая (`cost_usd`). Детали — в 3.5.

**Жёсткий антифрод (кратко; параметры и логика — в 3.5):** 3 попытки на аккаунт; не более 3 новых аккаунтов с одного IP в сутки; Cloudflare Turnstile перед каждой загрузкой фото и запуском генерации; почасовой и суточный потолки генераций на весь сайт.

**Аварийный выключатель ИИ (Kill Switch):**

- **В админ-панели**, раздел «ИИ»: переключатель «ИИ-зеркало включено / выключено», остаток бюджета ($10 − потрачено − зарезервировано), расход и число генераций сегодня и за последний час, редактируемые потолки (часовой, суточный), статус провайдера, журнал блокировок.
- **Автоматическое отключение** при: исчерпании бюджета (остаток меньше стоимости одной генерации); достижении суточного потолка (возобновление в 00:00 по Asia/Bishkek); доле ошибок провайдера выше 30% за 10 минут (circuit breaker). Алерт владельцу в Telegram при расходе 50%, 80% и 100% бюджета.
- **Поведение сайта при выключении:** флаг отдаётся через `/api/config` (кэш не более 60 с). Тизер на главной и раздел `/account/mirror` заменяются премиальным баннером в чёрно-золотом стиле: **«ИИ-зеркало на техобслуживании. Запишитесь к мастеру вживую — подберём образ на месте»** с кнопкой «Записаться». Загрузка и генерация блокируются на сервере (`503 AI_UNAVAILABLE`), ранее созданные результаты остаются доступны в течение срока хранения. В тексте нет слов «ошибка» и «лимит бюджета» — клиент видит только предложение записаться.

**Персональные данные и закон КР (Закон «Об информации персонального характера»):**

- **Согласие** на обработку персональных данных и биометрии — отдельный, не предзаполненный чекбокс перед первой загрузкой фото; текст на русском и кыргызском. Содержит: оператора, цель (виртуальная примерка причёсок), перечень данных (фото лица), третьих лиц, получающих данные (ИИ-провайдер), страну обработки, срок хранения, право отзыва и удаления. Подтверждение «мне исполнилось 18 лет».
- **Журнал согласий** (`consents`): версия текста, время, IP, user-agent, хэш текста.
- **Сроки хранения:** исходные фото — **7 дней**, результаты — **14 дней** (максимум), затем автоматическое удаление из S3 (Lifecycle-правило + ночной cron) и обнуление `storage_key` в БД. Пользователь может удалить фото и результаты досрочно в ЛК.
- **Трансграничная передача:** фото уходят ИИ-провайдеру за пределы КР. До запуска — согласовать с юристом КР требования к трансграничной передаче данных, регистрации держателя массива персональных данных и содержанию согласия; выбрать провайдера с политикой «не хранить данные и не обучаться на них» (проверка условий — на R&D).

**Типографика:** заголовки — высококонтрастный антиквенный serif (например, Playfair Display / Cormorant Garamond, с поддержкой кириллицы); текст и интерфейс — геометрический гротеск (Inter / Manrope). Шрифты self-hosted, `font-display: swap`, subset кириллица + латиница.

**Сетка и компоненты:** 4/8-px шкала отступов; брейкпоинты 360 / 768 / 1024 / 1440; минимальная touch-зона 44×44 px; радиусы 2–4 px (строгий премиум-стиль); тонкие золотые линии 1 px как декор. Библиотека компонентов в Figma: кнопки (primary-gold, secondary-outline, text), инпуты, чипы фильтров, карточки услуг/мастеров, слот времени, степпер, модалки, тосты, скелетоны.

### 2.2. Анимации и микро-взаимодействия

| Элемент | Поведение | Ограничения |
|---|---|---|
| **Прелоадер** | Чёрный экран, логотип прорисовывается золотой линией (SVG stroke), затем «шторка» раскрывается вверх; длительность 1,2–2,0 с | Показ 1 раз за сессию; скрывается сразу после загрузки критичных ресурсов, не дольше 3 с; не блокирует SEO-контент |
| **Hero** | Поэтапное появление: заголовок построчно (mask-reveal), подзаголовок, CTA; медленный параллакс/зум фона | easing `cubic-bezier(0.22, 1, 0.36, 1)` |

Обязательно: поддержка `prefers-reduced-motion` (анимации отключаются/упрощаются); анимируются только `transform` и `opacity`; 60 fps на среднем Android-устройстве; общий вес JS для анимаций ≤ 60 КБ gzip (динамические импорты).

### 2.3. Mobile-first и кросс-браузерные требования

- Проектирование начинается с 360×800; затем 390×844 (iPhone), 768, 1280+.
- **Запрет горизонтального скролла** на любых ширинах (`overflow-x: clip` на корне, проверка в CI скриншот-тестами).
- iOS Safari: использовать `100dvh`/`svh` вместо `100vh`, учитывать `env(safe-area-inset-*)`; авто-воспроизведение видео только с `muted playsinline`; фикс zoom-on-focus (шрифт инпутов ≥ 16 px); корректная работа `position: sticky/fixed` при смене адресной строки.
- Android Chrome: проверка на Chrome, Samsung Internet, MIUI-браузеры; экономия трафика (Save-Data → статичный постер вместо видео).
- Matrix тестирования: iOS 15+ Safari, Android 9+ Chrome, десктоп Chrome/Safari/Firefox/Edge (последние 2 версии). Тест на реальных устройствах (BrowserStack + минимум 3 физических).
- Навигация: на мобильном — бургер-меню на весь экран с анимацией + **sticky-кнопка «Записаться»** внизу экрана (скрывается на странице записи).

#### Главная `/`

- Два способа: **вход по номеру телефона (SMS-OTP 6 цифр, TTL 5 минут, 5 попыток, лимит отправок 3 в час на номер/IP)** и **«Войти через Google»**.

#### Виртуальное зеркало `/account/mirror`

Пользовательский сценарий (степпер из 4 экранов, адаптирован под мобильный):

1. **Загрузка фото.** Инструкция-схема (фронтально, ровный свет, без головных уборов и очков, волосы не закрывают лицо). Источники: камера (с контуром-подсказкой лица) или галерея. Клиентская предпроверка: размер, формат, разрешение. Прогресс загрузки.
2. **Проверка фото (не тратит лимит).** Серверная валидация и подготовка; пользователь видит статус «Фото принято ✓» или понятную причину отказа с советом. На этом шаге отображается: *«Проверка фото бесплатна и не расходует попытки»*.
3. **Выбор образа.** Каталог стилей: вкладки «Стрижки / Борода / Комбо», карточки с превью, поиск, избранное. Перед запуском — подтверждающий экран: *«Будет использована 1 из N попыток»*.
4. **Результат.** Анимация генерации (золотой shimmer, 10–40 с, возможность свернуть и вернуться), слайдер «До / После», действия: «Сохранить», «Поделиться», «Попробовать другой стиль» (тратит следующую попытку), **«Записаться с этим образом»** (стиль и референс прикрепляются к записи и видны мастеру).

*Состояния и ошибки:* лимит исчерпан → экран с благодарностью и CTA «Записаться к мастеру» (+ задел под платные пакеты попыток); сбой генерации → автоматический возврат попытки и сообщение; сетевая ошибка → безопасное восстановление статуса по `jobId`.

#### Контакты `/contacts`

Адрес, интерактивная карта (Google/2GIS/Яндекс с тёмной темой), часы работы, телефон, WhatsApp/Telegram, кнопка «Построить маршрут», форма обратной связи.

### 3.5. Бизнес-логика лимитов ИИ и защита бюджета ($10)

Принцип: **три независимых лимита** — на аккаунт (3 бесплатные попытки), на IP/сайт (антифрод и потолки в час и в сутки) и на деньги (бюджет $10). Все проверки выполняются только на сервере; генерация запускается, только если проходят все. Проверки идут от дешёвых к дорогим, чтобы бот упирался в защиту раньше, чем в платный вызов.

#### Параметры (настраиваются в админке, хранятся в `salon_settings` и `ai_budget`)

| Контроль | Значение по умолчанию | Зачем |
|---|---|---|
| Попытки на аккаунт | 3 бесплатных (`ai_free_limit`) | Основной лимит из ТЗ |
| Новые аккаунты с одного IP | не более 3 за 24 ч (IPv4 — /32, IPv6 — /64) | Против мультиаккаунтов |
| Генерации с одного IP | не более 9 в сутки (3 аккаунта × 3 попытки) | Страховка, если лимит аккаунтов обошли |
| Загрузки фото на аккаунт | не более 5 в сутки | Защита от перебора и нагрузки на CPU |
| Cloudflare Turnstile | перед каждой загрузкой фото и перед запуском генерации; токен одноразовый, проверяется на сервере (`siteverify`) | Против ботов, которые «скликают» бюджет |
| Потолок генераций в час (весь сайт) | 5 | Бюджет нельзя сжечь за час |
| Потолок генераций в сутки (весь сайт) | 15 (формула: остаток бюджета ÷ цена генерации ÷ плановые дни работы) | Равномерный расход |
| Бюджет | $10; резерв на вызов = максимальная цена генерации | Жёсткий денежный потолок |
| Допуск к ИИ | аккаунт с подтверждённым Google (`email_verified`) или подтверждённым по SMS телефоном; одноразовые email-домены блокируются | Против одноразовых аккаунтов |

Особенность КР: мобильные операторы используют общий IP для многих абонентов (CGNAT), поэтому жёсткий IP-лимит может блокировать реальных клиентов. Меры: при превышении сначала усиливается Turnstile (интерактивный режим), а не выдаётся отказ; в whitelist добавляется IP салона (демонстрация сотрудниками); лимит учитывает также cookie устройства; все срабатывания пишутся в `ai_abuse_log` и анализируются после первой недели.

#### Таблицы, добавляемые к 3.4

- **`ai_budget`** (одна строка): `budget_usd` (10.00), `spent_usd`, `reserved_usd`, `est_cost_usd` (максимальная цена одной генерации), `hourly_cap`, `daily_cap`, `kill_switch bool`, `kill_reason enum(manual, budget, daily_cap, provider_errors)`, `updated_at`.
- **`ai_abuse_log`**: `id`, `user_id NULL`, `ip`, `device_id`, `rule` (ip_accounts, ip_generations, turnstile_failed, cap_hour, cap_day), `created_at`.
- **`consents`**: `id`, `user_id`, `type` (personal_data, biometric_ai), `text_version`, `text_hash`, `ip`, `user_agent`, `created_at`, `revoked_at`.
- Для `ai_generations` добавляется `reserved_cost_usd` и `cache_hit bool`.

#### Шаг 1. Загрузка и проверка фото (лимит попыток не списывает)

`POST /ai/photos` с токеном Turnstile: проверка токена → согласие `biometric_ai` и подтверждение 18+ → лимит загрузок → клиентская и серверная валидация (одно лицо, ракурс, размер, NSFW) → статус `approved` / `rejected`. Платных вызовов на этом шаге нет, лимит попыток не расходуется. Сразу выставляется `expires_at` (+7 дней).

#### Шаг 2. Запуск генерации (списание попытки и резерв бюджета)

`POST /ai/generations { photoId, styleId }` с заголовками `Idempotency-Key` и токеном Turnstile. Проверки по порядку, на первом отказе остановка:

1. **Kill switch** выключен и ИИ-зеркало доступно → иначе `503 AI_UNAVAILABLE` (клиенту показывается баннер «ИИ на техобслуживании», см. 1.5).
2. Turnstile валиден → иначе `403 CAPTCHA_FAILED`.
3. Фото `approved` и принадлежит пользователю; аккаунт допущен к ИИ.
4. Идемпотентность: если генерация с таким ключом уже есть — вернуть её, без нового списания.
5. Кэш: есть результат для (sha256 фото, стиль, версия модели) → вернуть его, **без списания попытки и без расхода бюджета** (`cache_hit = true`).
6. Лимиты IP (аккаунты и генерации) → иначе `429 AI_IP_LIMIT`.
7. Потолки сайта в час и в сутки (счётчики Redis, TTL до конца окна по Asia/Bishkek) → иначе `503 AI_BUSY` с текстом «попробуйте завтра или запишитесь к мастеру».
8. **В одной транзакции БД** — резерв бюджета и списание попытки:

```sql
UPDATE ai_budget
SET reserved_usd = reserved_usd + est_cost_usd, updated_at = now()
WHERE id = 1 AND kill_switch = false
  AND spent_usd + reserved_usd + est_cost_usd <= budget_usd;

UPDATE ai_quotas
SET used_count = used_count + 1, updated_at = now()
WHERE user_id = $1
  AND used_count < free_limit + bonus_count;
```

9. Если любой из двух `UPDATE` не затронул строку — откат транзакции: нет бюджета → `503 AI_UNAVAILABLE` (и автоматически включается kill switch с причиной `budget`); нет попыток → `402 AI_LIMIT_EXCEEDED`.
10. Создать `ai_generations` (`queued`, `quota_charged = true`, `reserved_cost_usd`), записать в `ai_quota_ledger`, поставить задачу в BullMQ.

#### Шаг 3. Результат, возвраты и учёт расходов

- `succeeded` → сохранить результат в S3 (хранится 14 дней), записать фактическую стоимость: `spent_usd += cost_usd`, `reserved_usd -= reserved_cost_usd`; вернуть подписанный URL.
- `failed` / таймаут / отказ фильтра безопасности провайдера → **автоматический возврат**: `used_count − 1`, запись в ledger, статус `refunded`, освобождение резерва бюджета (`reserved_usd -= reserved_cost_usd`). Возврат выполняется строго один раз (`quota_refunded_at IS NULL`).
- Остаток бюджета сверяется с кабинетом провайдера раз в неделю (и при каждом пополнении); расхождение больше 10% — алерт владельцу.

#### Автоотключение и мониторинг

- Остаток бюджета меньше `est_cost_usd` → `kill_switch = true`, причина `budget`; суточный потолок исчерпан → ИИ скрыт до 00:00 по Asia/Bishkek (причина `daily_cap`); ошибки провайдера выше 30% за 10 минут → причина `provider_errors`.
- Telegram-алерт владельцу при расходе 50%, 80% и 100% бюджета и при каждом срабатывании `ai_abuse_log` выше порога (например, более 20 блокировок за час).
- Включить ИИ обратно может только owner/admin из раздела «ИИ» (после пополнения бюджета или смены лимитов).

**Серверные гарантии:** лимит никогда не проверяется только на клиенте; счётчик не сбрасывается при удалении фото, результатов или повторном входе; один аккаунт Google или один телефон = одна квота; при удалении аккаунта хэш идентификатора остаётся в `blocked_identities`, чтобы нельзя было получить новые 3 попытки повторной регистрацией. Бонусные попытки администратор начисляет вручную (`admin_grant`), каждое действие логируется.

## 4. Пошаговый план разработки (Roadmap)

Ориентировочная длительность — **14–16 недель** при команде: PM, UI/UX-дизайнер, 2 frontend, 1–2 backend, QA, DevOps (part-time).

## 5. Риски и меры снижения

| Риск | Мера |
|---|---|
| Низкое качество ИИ-результата (искажение лица, неестественные волосы) | Бенчмарк на этапе R&D, строгая предвалидация фото, ручная настройка промптов, дисклеймер на результате, возврат попытки при явном сбое |
| Высокая стоимость генерации | Лимит на аккаунт, дешёвая модель по умолчанию, общий дневной бюджет и «аварийный выключатель» в админке, мониторинг `cost_usd` |
| Мультиаккаунты для обхода лимита | Обязательная верификация телефона, антифрод-правила, `blocked_identities` |
| Юридические риски (биометрия, персональные данные) | Явное согласие, хранение фото 7–14 дней, кнопка удаления, консультация юриста по законодательству вашей страны |
| Тяжёлые анимации и видео ломают мобильную производительность | Бюджеты производительности, `prefers-reduced-motion`, poster-фолбэк, тесты на бюджетных Android |
| Двойные брони и «призрачные» слоты | Ограничение на уровне БД + soft-lock + нагрузочное тестирование |
| Зависимость от одного ИИ-провайдера | Интерфейс `AiProvider` и резервный провайдер |
| Недостаток качественного контента | Фото- и видеосъёмка в плане с этапа 2, медиа-гайд для фотографа |
